# Paramètres › Apparence — thèmes de couleur (2026-08-19)

Demande utilisateur : « un seul thème aujourd'hui ; dans Paramètres, pouvoir choisir un autre thème de couleur, bien fait, sans contrainte visuelle, et que Lighthouse passe ». Décisions (AskUserQuestion) : **par utilisateur** (pas par établissement) · **4 palettes** en plus de Lavande · **nouvel onglet « Apparence »** + la même carte dans `/admin/system/settings`. Mode sombre hors périmètre (chantier distinct : 28 `bg-white` / 60 `text-white` à auditer).

## Mécanique
- **Tokens** : l'app ne connaît que les tokens `@theme` de `globals.css` (`text-primary` ×249, `bg-card` ×137…). Un thème = un bloc `:root[data-theme='x']` qui surcharge **exactement** 16 tokens de marque/teinte (`background`, `foreground`, `border`, `muted(-foreground)`, `primary(-foreground)`, `secondary(-foreground)`, `accent(-foreground)`, `primary-gradient-end`, `card-foreground`, `sidebar-light-foreground`, `sidebar-dark(-foreground)`). Lavande = le `@theme` de base, sans bloc. Couleurs **non** thémées volontairement : statuts (success/warning/destructive/info), or (plan payant), charts admin (palette CVD validée), matières/avatars (couleurs de données), `--color-card` (blanc), et le nouveau `--color-bulletin-gradient-end` (le bulletin imprimé est rendu sans thème par le pipeline PDF → l'aperçu ne doit pas en dépendre).
- **Registre** `src/lib/themes.ts` : `THEME_KEYS` (lavande | ocean | foret | ardoise | terracotta), labels/descriptions, `swatch` (3 couleurs d'aperçu = les tokens CSS, vérifié par test), `applyThemeToDocument`, `THEME_INIT_SCRIPT`.
- **Pas de flash** : `app/layout.tsx` injecte `THEME_INIT_SCRIPT` dans `<head>` (lit `localStorage['sg-theme']`, pose `data-theme` sur `<html>` avant le premier rendu ; CSP `script-src 'unsafe-inline'` déjà requis par l'App Router) + `suppressHydrationWarning` sur `<html>` uniquement.
- **Provider** `contexts/ThemeContext.tsx` (`useTheme()` → `{ theme, setTheme }`) sous `AuthProvider` : `setTheme` stampe `<html>`, écrit localStorage et `PATCH /api/auth/me { theme }` ; au chargement de l'utilisateur, la valeur serveur gagne une fois par session (nouvel appareil, stockage vidé).
- **Persistance** : `User.theme String?` (migration `30_user_theme`), `GET /api/auth/me` renvoie `theme` (valeur inconnue → `null`), `PATCH` accepte `z.enum(THEME_KEYS).nullable()` (400 sinon). `AuthContext.User.theme`.
- **UI** : `components/settings/ThemePicker.tsx` — radiogroup de vignettes (miniature sidebar sombre / page teintée / carte blanche / bouton primaire / puce secondaire peinte avec les couleurs **du thème de la vignette**), tabindex tournant + flèches/Espace/Entrée (même contrat que `PlanCards`), application immédiate + toast, « · Par défaut » sur Lavande, note contraste. Consommé par `(school)/settings/ApparenceTab.tsx` (onglet après Profil, `?tab=apparence`) et la section `#appearance` de `/admin/system/settings` (hors du bouton Enregistrer : préférence personnelle).
- **Fuites de violet corrigées** pour suivre le thème : donut répartition par niveau (`color-mix(var(--color-primary), white)`), dégradé fiche élève, encadrés `border-[#c4b5fd] bg-[#f5f3ff]` ×3 → `border-primary/30 bg-secondary`, carte sombre du modal Créer une école → `bg-sidebar-dark`, icônes du panneau login → `text-sidebar-dark-foreground`, texte « Paiement traité par Stripe » → `text-primary` (était 4,4:1, désormais AA).

## Garantie accessibilité (Lighthouse `color-contrast`)
- `src/lib/themes.test.ts` **lit `globals.css`**, résout chaque thème (base + surcharges) et vérifie ≥ 4,5:1 (WCAG AA) sur 26 paires texte/fond réellement rendues (primary sur card/background/secondary/muted, blanc sur primary, secondary-fg sur secondary, muted-fg sur card/background/muted/secondary, foreground partout, sidebar sombre : texte, blanc, `white/50` des items inactifs, statuts success/warning/destructive/info sur background et card), + ensemble de tokens identique pour tous les thèmes, + swatches = CSS, + script pré-paint valide. Un nouveau thème qui casse une paire fait échouer `pnpm test`.
- Palettes calibrées (min observé) : Lavande 4,66 · Océan 4,51 · Forêt 4,51 · Ardoise 4,85 · Terre cuite 4,75 (toutes les autres paires bien au-dessus).
- Audit Lighthouse réel (2026-08-19, build prod servi en local sur :3001 avec l'env de dev, Chrome partagé puppeteer-login + Lighthouse `disableStorageReset`) : **accessibilité 100 / bonnes pratiques 100 pour les 5 thèmes × 5 pages** (`/dashboard`, `/settings?tab=apparence`, `/eleves`, `/configuration/classes`, `/abonnement`), `color-contrast` 0 élément ; landing + login : a11y 100. Deux défauts préexistants (identiques en Lavande) corrigés au passage : initiales d'avatar blanches sur vert/orange/teal (3,3–3,8:1 → palette assombrie, ≥ 5:1) et `FilterSelect` (`role="combobox"` sans nom accessible → `aria-labelledby` sur sa valeur, prop `ariaLabel` optionnelle).
- E2E Puppeteer (24 vérifications) : 5 vignettes, Lavande cochée par défaut sans attribut, clic Océan → `html[data-theme=ocean]` + `--color-primary=#1e40af` + PATCH `{theme:'ocean'}` 200 + localStorage + toast, rechargement : attribut déjà présent au `DOMContentLoaded` (pré-paint), `GET /api/auth/me` = ocean, nouvel appareil (contexte vierge) → thème serveur appliqué après login, ←/→ au clavier (focus + sélection), dashboard dans les 5 thèmes, carte admin `#appearance` (5 vignettes, nav, Ardoise appliqué).

## Pour ajouter un thème
1. Bloc `:root[data-theme='x']` dans `globals.css` avec les 16 tokens ; 2. entrée dans `THEMES` (`src/lib/themes.ts`) avec swatch = tokens ; 3. `pnpm test` (contraste + cohérence) ; rien d'autre à toucher (API/zod/UI dérivent de `THEME_KEYS`).
